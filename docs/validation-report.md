# 有效性测试报告（v0.1.2）

> ⚠️ 本报告包含 **v0.1.2 基线**核验与 **v1.0.0 增量**核验（最近两次）；v1.0.0 起新增的三预设切换、交付证据门禁 `dev_delivery_check`、上游引导层对齐等行为以 `README.md` / `CHANGELOG.md` 为准。

> 本报告汇总本套件在真实 Codex 会话中的有效性核验记录。所有会话标识、项目路径、用户文本与时间信息均已匿名化处理。

## 核验方式

- 读取套件状态文件与会话 rollout 记录，核对：主会话唯一形态（`model_instructions_file`）是否生效、persona 注入次数与用户消息是否一一对应、首轮锚定与提升状态、模式分类、计划模式行为。
- 对发现的行为差异，用真实会话输入回放钩子复现，并修复后回归。

## 用例与结果

### 用例 1：计划模式会话（新建会话）

**场景**：用户在计划模式下新建会话，首条消息为“阅读某项目并规划移植方案”类任务。

**核验项**

- 主会话唯一形态生效：会话基础指令为 RL 句 + 路由规则 ✓
- 计划模式下 persona 注入次数与用户消息一一对应 ✓（早期版本曾因桌面端未上报 `permission_mode` 而漏判，已修复；后续统一为 DSH 原始语义：plan 段由宿主保留，路由器照常注入/锚定）
- 模式分类、锚定状态、状态文件与会话记录一致 ✓

**结论**：通过（过程中发现并修复 1 个计划模式识别问题）。

### 用例 2：模糊任务会话（新建会话）

**场景**：首条消息未命中构建/修复关键词，进入 weak 内部路由。

**核验项**

- weak 内路由生效（状态 band=weak）✓
- 状态工具显示的 persona 与实际注入文本一致 ✓（早期曾显示不一致，已修复）
- 首个核心工具调用后 `promoted=true`，工具目录全量放开，无错误拒绝 ✓

**结论**：通过。

### 用例 3：多轮复杂会话（跨安装、续接、计划模式）

**场景**：会话创建早于套件安装，中途安装启用，之后续接并切换过计划模式；任务为硬件调试类（fix）。

**核验项**

- 安装前发生的工具调用不产生锚定拒绝（钩子尚未生效，符合预期）✓
- 安装后真实用户消息的 persona 注入一一对应 ✓；续接段唯一未注入的是宿主注入的环境上下文消息（无用户文本，符合预期）✓
- 首轮工具调用为核心工具，`promoted=true`，全程无错误拒绝 ✓
- 计划模式下 persona 照常注入（DSH 对等语义）✓
- 分类为 spec（调试类），复杂度标记正确，状态文件与会话记录一致 ✓

**结论**：通过。

### 用例 4：standard 预设（首轮无指令，v1.0.0 增量）

**场景**：新建会话使用默认 `standard` 预设，首轮未带 `#preset` 指令，任务为“检查仓库是否有更新”类（无强分类关键词）。

**核验项**

- 状态文件写入新路径 `~/.codex/codex-dsh-routing-suite/state/`，旧路径无残留 ✓（验证 ROUTER_HOME 改名遗漏修复）
- 首轮无指令时直接采用 `config.json` 的 `preset`（默认 `standard`）✓
- `firstUserText` 无任何指令残留 ✓
- 分类为 weak（无强关键词）✓；复杂度 false；`promoted=true` ✓

**结论**：通过。

### 用例 5：spec 预设（首轮 `\#preset` 指令，v1.0.0 增量）

**场景**：首轮以 `\#preset spec`（Markdown 反斜杠转义）指定 spec 预设，任务为“拉取上游更新并分析移植方案对齐”类。

**核验项**

- 转义指令被识别并剥离，`firstUserText` 不含指令文本 ✓（验证 `\#preset` 识别修复）
- `preset=spec`，`mode=0 / band=spec`，固定深思考，忽略任务分类与 override ✓
- 复杂度 true（含“分析/方案/移植”）✓；`promoted=true` ✓

**结论**：通过。

## 回归与结论

- v0.1.2 基线核验共发现并修复 3 类问题：计划模式识别（桌面端 `permission_mode` 缺失）、状态工具 persona 显示不一致、模型门控判定过宽（其他厂商 `*-flash` 误判，已改为仅 DeepSeek 家族生效）。
- v1.0.0 增量核验共覆盖 2 类场景（standard 默认 + spec 固定预设），并验证修复 2 个问题：`ROUTER_HOME` 仍指向旧路径（改名遗漏）、`\#preset` 转义写法未识别。
- 回归测试：仓库 58 例全部通过（v0.1.2 时点为 39 例）；安装/卸载、双后端、模型门控、交付门禁均有自动化用例覆盖。
- 总体结论：核心路由行为（分类、注入、锚定、提升、计划模式、续接、模型门控）在真实会话中符合预期。
